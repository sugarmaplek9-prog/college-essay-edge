## 3. Re-evaluation criteria

Items in this list should be re-evaluated when:

* v1.0.1 has been successfully deployed and monitored
* The next planned release cycle begins
* New evidence emerges that changes the priority or feasibility
* Dependencies (e.g., third-party updates) become available

## 4. Process for re-inclusion

To move an item from deferred to active:

1. Update evidence and impact assessment
2. Re-score using the prioritization model from V1_0_1_HOTFIX_PLAN.md
3. Get product + engineering approval
4. Add to the appropriate sprint or release plan

## 5. Notes

* This list should be reviewed weekly during the first month post-v1.0.1
* Items with high user impact or revenue risk should be escalated for earlier consideration
* Non-critical items may remain deferred indefinitely if they don't meet inclusion criteria for future releases
